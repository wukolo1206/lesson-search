## 2026-02-28 圖片顯示功能完成 & 部署問題修復

### 一、Google Drive 圖片嵌入功能

#### 試算表使用方式
在試算表的「文章全文」欄位，使用以下格式嵌入圖片：

```
[GDrive: 圖片的檔案ID]
```

- 圖片 ID 取自 Google Drive 連結中 `id=` 後面的那串英數字
- 例：連結為 `https://drive.google.com/file/d/1SVB9tBFb.../view`，則 ID 為 `1SVB9tBFb...`
- **注意**：Google Drive 圖片所屬的資料夾必須設定「知道連結的任何人 → 檢視者」才能正常顯示

#### 前端實作注意事項（index.html formatPresText）
- 圖片必須用 DOM API `document.createElement('img')` 建立，**不能**在 JS 字串裡寫 `<img>` HTML 標籤（GAS 的 `document.write()` 無法處理，會造成 SyntaxError crash）
- 圖片網址用 Google Drive 縮圖 API：`https://drive.google.com/thumbnail?id=ID&sz=w1200`（不用 `/uc?id=`，那個有 CORS 限制）
- 點擊圖片可全螢幕 Lightbox 放大，按任意處或 ESC 關閉（`openPresImageLightbox` 函數）

---

### 二、段落切換功能（原段落 / 自動分段）

- 加入 `togglePresFormatMode()` 函數與 `presFormatMode` 狀態（'original' 或 'auto'）
- **重要**：按鈕文字與 JS 字串**不能使用 emoji**（如 `📝` `🔄`），GAS 無法正確編碼，會造成整頁 SyntaxError

---

### 三、GAS 部署正確做法

每次修改程式碼後，必須：
```bash
clasp push
clasp deploy -i <部署ID>   # 一定要指定 ID，否則會產生新 URL，舊連結就全部失效
```

快速更新所有現有部署的 Python 腳本（存於根目錄，deps2.txt 記錄所有部署ID）：
```python
import subprocess
out = open("deps2.txt", encoding="utf-8").read()
lines = [l.strip() for l in out.split("\n") if l.strip().startswith("- ")]
subprocess.run("clasp push", shell=True)
for line in lines:
    if "@HEAD" not in line:
        dep_id = line.split(" ")[1]
        subprocess.run("clasp deploy -i " + dep_id, shell=True)
```

---

### 四、常見錯誤與解法

| 錯誤 | 原因 | 解法 |
|---|---|---|
| `SyntaxError: Invalid or unexpected token` | JS 字串含 emoji 或全形符號 | 改用純 ASCII 或 `\uXXXX` Unicode 跳脫 |
| `SyntaxError: Failed to execute write on Document` | JS 字串含 `<br>` / `<img>` 等 HTML 標籤 | 改用 `document.createElement()` DOM API |
| 頁面 spinner 不停，0 篇教材 | `getData()` 讀取 585 行超大欄位導致 GAS 超時 | `Code.js` 略過大型欄位（如「遷移文本內容」） |

---

### 五、試算表資料注意事項

- 「文本標題」欄**不能有前後多餘空白**，否則同篇文章會被視為兩篇不同文章、出現兩張卡片
  - 修正方法：在 Google Sheets 用 `Ctrl+H` 全域取代，或直接點格子修改
- 「年度」、「年級」欄格式必須統一（例如都用 `114`，不混用 `114年`）
- 「學習遷移題目」工作表的「遷移文本內容」欄很長，`getData()` 已設定略過此欄（避免超時）

## 學習遷移題目：生成邏輯更新

為了確保遷移題目的設計與原始文章的結構一致（一篇文章配多個題目），我們需要調整自動生成的配對邏輯：

### 核心概念：文章對文章 (Article-to-Article Mapping)
原本的邏輯是「題目對題目，隨機挑文章」，這會導致同一篇原始文章的三個題目，可能被分散對應到三篇不相關的補充文章。

現在的正確邏輯是：
1. **以「原始文章」為單位**：找到一篇原始文章（例如「三年級：我的小貓」），這篇文章底下有 3 個題目（可能分別測驗提取、推論、大意）。
2. **尋找 3 篇「補充文章」來做大遷移**：我們從補充庫中，挑出 **3 篇不同的** 三年級補充文章（例如「小黃狗」、「去郊遊」、「洗澡了」）。
3. **分配考點**：
    *   將這 3 篇「補充文章」，**各自**設計出那 3 個考點的題目。
    *   換句話說，如果原文章考了 (1)提取 (2)推論 (3)大意。那麼：
        *   補充文章A：會產生 (A-1)提取、(A-2)推論、(A-3)大意。
        *   補充文章B：會產生 (B-1)提取、(B-2)推論、(B-3)大意。
        *   補充文章C：會產生 (C-1)提取、(C-2)推論、(C-3)大意。

**這樣一來：**
*   學生在練習「小貓（原文章）」的「推論題」時，老師可以切換到「小黃狗（補充文章A）」、「去郊遊（補充文章B）」或「洗澡了（補充文章C）」的推論題進行遷移。
*   而且這 3 篇補充文章，本身也是「完整」的閱讀測驗（各包含三個難度的題目），可以直接單獨作為試卷使用！

## 2026-02-28 簡報模式圖文混排修正 (版本 @104)

### 問題描述
在簡報模式（index.html formatPresText）中，當「文章全文」欄同時包含 [GDrive: ID] 圖片標籤 **與** 文章文字時，圖片顯示為破圖（瀏覽器顯示 Click to enlarge 提示）。
純圖片（欄位只有 [GDrive: ID]，無其他文字）可正常顯示。

### 根本原因
自動分段邏輯（auto 模式）會將 [GDrive: ID] 標籤和與其相臨的 5 個中文句子**合併進同一個 <p> 段落**，導致圖片被混入文字段落渲染失敗。

### 修正內容 (index.html)
1. **圖片 URL 修正**：將 Google Drive thumbnail URL 改為 lh3.googleusercontent.com/d/ID=w1200，相容性更佳；並加入 onerror 備援，失敗時自動改回 thumbnail URL。
2. **分段邏輯修正**：讓 [GDrive: ID] 圖片標籤**永遠獨立成一個段落**，不與任何中文句子合併。圖片段落前後的文字才按 5 句一段重新組合。
3. lt 與 	itle 屬性清空（lt='', 	itle=''），避免破圖時顯示多餘文字。

# ===== 2026-03-08 學生自主練習系統開發與整合 =====

## 第六階段任務： 開發學生練習網頁並整合至 Google Apps Script (GAS)

### 一、任務背景與設計決策
為了解決外校老師及學生無法使用原先需要老師權限分配的測驗系統（避免隱私與授權問題），開發了「免登入、純前端」的學生專屬自主練習系統。
最初方案透過 GitHub Pages 發布並直接讀取公開的 CSV 資料，但遭遇部署網址不一、以及潛在的跨域請求 (CORS) 擋截問題，最後決議**回歸單一網址架構，完美整合入現有的 GAS (Google Apps Script) 專案中**。

### 二、實作流程與架構
1. **本機分離開發 (`student_app/`)**：
   建立獨立的 `student_app/index.html`, `app.js`, `style.css`。實作包含：
   - 使用者登入介面 (班級、座號、姓名)。
   - 「年級 → 文章」兩階段智慧下拉選單 (含自訂排序權重)。
   - 即時批改介面與自動排版本文。
   - 運用 `html2canvas` 實作一鍵產生成績卡圖檔供下載交差。
   - 內建 `SweetAlert2` 製作的「教師加題指南」對話框。
2. **開發環境備援機制 (CSV fallback)**：
   在 `app.js` 中實作偵測：如果是在原生的網頁上，啟用 `PapaParse` 下載 Google Sheets 的公開 CSV；若在 Google Apps Script 原生環境，則直接透過 `google.script.run` 呼叫安全的後端 API。
3. **自動內聯打包腳本 (`scripts/build_student_practice.py`)**：
   為了克服 GAS 無法引用外部 js/css 檔案的限制，開發了一支 Python 腳本。它能一鍵把 `student_app/` 底下的 CSS (`<style>`) 和 JS (`<script>`) 讀出並注入 HTML 檔，最終輸出一個能完美被 GAS 讀取的單檔 `student_practice.html`。
4. **GAS 後端路由 (`Code.js` & `index.html`)**：
   - 修改 `Code.js` 裡的 `doGet(e)` 函式，新增 `?page=self_practice` 路由導向新的 html。
   - 更改 `index.html` 首頁按鈕，使用原生 `<?= ScriptApp.getService().getUrl() ?>` 以相對路徑方式確保無論發布 ID 如何改變，連結都正確。
5. **發布與覆蓋部署 (`Deploy V130`)**：
   使用 `clasp` 指令將合併後的程式碼推上雲端，並使用 `clasp deploy -i [部署 ID]` 強制覆蓋了原有的網址版本 (V129 → V130)，達成不換網址的完美升級。

# ===== 2026-03-08 考古題 PDF 跳轉 Github Pages 實作 =====

## 第七階段任務： 解決 Google Drive 預覽器無法精準跳頁與滿版的問題

### 一、問題描述與技術限制
在 @140 版本中，系統已具備依照「年度_年級_標題」對齊，並取得每一篇文章所屬試卷對應「頁碼」的能力，並且在介面上提供「考古題試卷」的按鈕。
然而，原先設計將檔案存放於 Google Drive 且透過 `https://drive.google.com/file/d/ID/view` 跳轉的作法遭遇到技術限制：
- **Google Drive 懶加載 (Lazy Load)** 限制：無法透過 `#page=N` 強制跳轉至預期頁碼。
- **無彈性參數**：無法傳入自動滿版 (`#view=FitH`) 等屬性，導致排版無法控制且學生有機會滑動偷看其他章節。

### 二、實作解決方案：結合 GitHub Pages 靜態代管 (V142)
為了避開上述限制，最終決定採用跨專案支援的「Github Pages 原生 PDF 渲染」解決方案（方案一），將檔案遷移至穩定佈署中的「字音形系統」專案。

#### 1. 批量重命名過渡檔名 (Python 腳本)
撰寫並執行本地轉換腳本 `copy_pdfs.py` 與 `copy_pdfs_2.py`：
- 將複雜的中文原名（包含 108年 到 114年），透過 Regex 分析並萃取年度與年級。
- 自動轉換為統一規格之 `114_G3.pdf`，並**自動從原始目錄複製到 `字音形系統/pdf/` 內**，達成 24 份各年份考古題的全數建檔。

#### 2. 前端串接網址改寫
修改 `index.html` 中的 `makeExamBadge` 函數：

- 直接拼接 `https://wukolo1206.github.io/pdf/` + `年度_年級.pdf`。
