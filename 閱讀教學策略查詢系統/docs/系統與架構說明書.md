# 閱讀教學策略查詢系統 - 系統架構與開發指南

這份文件記錄了「閱讀教學策略查詢系統」的整體專案架構、核心功能、技術棧與程式碼邏輯，旨在幫助未來的開發與維護工作，減少重複摸索的時間。

---

## 1. 專案概述 (Project Overview)
本系統主要提供教師與學生一個快速查詢、檢視及測驗學習扶助「閱讀」與「字音字形」相關考題與策略的平台。
- **目標使用者**：國小補救教學/學習扶助教師、參與學習扶助的學生。
- **主要資料來源**：Google Sheets (`學習扶助閱讀測驗試題分析.xlsx` 匯入)。
- **託管平台**：
  - 後端 API 與 Web App 主應用：Google Apps Script (GAS)
  - 靜態資源 (含 PDF 試卷、圖檔)：GitHub Pages (`wukolo1206.github.io`) & Google Drive。

---

## 2. 系統架構 (System Architecture)

採用**前後端分離**但建置在同一個 GAS 專案上的單頁應用 / 多頁應用混合架構。

### 🛡 前端技術棧 (Frontend)
- **HTML/CSS**：使用原生 HTML，搭配 **Tailwind CSS** (透過 CDN) 快速建構乾淨、現代化且支援 RWD 響應式的版面。
- **JavaScript 邏輯**：
  - 原生 Vanilla JS 用於前端路由、資料過濾 (Filter)、以及 Modal 彈窗控制。
  - `sweetalert2` 用於精美的警告與提示視窗 (例如：交卷確認、測驗結果)。
- **圖示庫**：FontAwesome 或內建的 Emoji emoji 作為 Icon。

### ⚙️ 後端技術棧 (Backend)
- **Google Apps Script (GAS)**：
  - `Code.gs`: 負責接收 HTTP `GET` 請求並回傳對應的 HTML 頁面 (透過 `HtmlService`)。
  - 還負責讀取 Google Sheets 的備用資料或者做為簡單的 Web API (透過 `google.script.run`)，以便前端與表單、試算表溝通。
- **外部資源伺服器 (CDN/Static)**：
  - 由於 GAS 載入外部 PDF 易有限制，多數考古題 PDF (如 `109_G3.pdf`) 已透過 Python 腳本清洗檔名並上傳至 **GitHub Pages** 的 `pdf/` 目錄下以提供更穩定、可帶參數定位 (如 `#page=5&view=FitH`) 的 PDF 預覽。

## 3. 專案目錄結構 (Directory Structure)

以下是開發環境 (本機端) 中的目錄結構。透過 `clasp` 工具，這些檔案會被轉譯並推送到 GAS 上。

```text
閱讀教學策略查詢系統/
│
├── .clasp.json                  # clasp 設定檔 (決定 push 到哪個 GAS 專案)
├── appsscript.json              # GAS 的權限與 OAuth 範圍設定
│
├── Code.js                      # [後端] GAS 的主要進入點，包含 doGet() 與資料庫互動邏輯
│
├── index.html                   # [前端] 【首頁/題庫查詢核心】 - 教師用主要入口，負責策略過濾、搜尋引擎與題目列表
├── teacher.html                 # [前端] 【教師簡報模式】 - 為上課展示所設計的純淨版模式
├── student_practice.html        # [前端] 【學生線上測驗】 - 學生自主閱讀與作答平台
├── quiz.html                    # [前端] 【字音字形測驗】 - 專門負責語文基礎單詞、部首的測驗頁面
│
├── output/                      # [資料檔] 從 Excel 表格匯出的靜態 JSON 或 JS 資料陣列 (ex. batchUpdateArticles.js)
├── docs/                        # [文件] 專案開發紀錄、會議紀錄與這份系統架構文件
└── scripts/                     # [工具] 維護專案的 Python 腳本 (如：把 OOO 換成特定關鍵字、自動重新命名 PDF 並分類等)
```

## 4. 核心功能與程式碼邏輯指南

### 4.1 核心查詢邏輯 (`index.html`)
- **生命週期**：頁面載入時 ( `window.onload` ) 會預先讀取嵌入在 HTML / 變數中的 JSON 資料庫 (例如 `rawData` 陣列)。
- **過濾機制 (Filter)**：
  - `filterData()` 函式是核心。它會根據使用者目前選擇的「年級」、「年段」、「檢測指標」、「向度」來 `filter` 出符合條件的資料列。
  - 過濾後透過 `renderCards()` 動態建立 HTML 結構 (字串拼接 / DOM 操作) 並渲染到畫面上。
- **Card 的動作**：
  - 點擊「👁️ 原卷閱讀」會觸發 `openModal()`，從 GitHub Pages 讀取對應的試卷 PDF 放進 `iframe`，並帶上 `#page=X&view=FitH` 來定位頁面。

### 4.2 簡報與學生測驗模式 (`teacher.html` & `student_practice.html`)
- **資料傳遞**：由於這兩個頁面是作為「跳轉」，系統主要利用 URL 參數 (例如 `?mode=teacher&id=123`) 將需要顯示的題目 ID 傳給新頁面。
- **閱讀介面**：它們拋棄了 PDF，直接拿取預先清理好的「純文字題目與文章 (文章內容、題幹、選項)」，利用 CSS 排版成乾淨的閱讀視窗，學生閱讀時文字可以任意放大，不會有排版跑掉的問題。

### 4.3 題庫結構與資料生成
本案不是把幾千筆資料動態從 Sheets 抓取 (因為 GAS 會太慢)，而是**建置時生成靜態包 (Build-time Static Generation)**。
1. Excel 表單如果有更新 (`學習扶助閱讀測驗試題分析.xlsx`)。
2. 執行根目錄下或是 `scripts/` 中的 Python 重構腳本。
3. 把洗好的 JSON 直接「寫進」 `output/` 裡的 `.js` 或 HTML 檔案中 (例如：將 2500 題的 array 寫死在前端變數 `const rawData = [...]` 中)。
4. `clasp push` 上去後，前端一開網頁資料就在記憶體中了，速度最快。

## 5. 常見維護場景 (How-to Guide)

### ❓ 情境一：未來如果有「新的考題」要加入系統？
1. 更新本機的 Excel 原始檔 (`學習扶助閱讀測驗試題分析.xlsx`)。
2. 執行 Python 腳本 (如 `scripts/batch/dump_batch_x.py` 或彙整腳本)，將新資料抽取成 JSON / JS 變數，並更新到 HTML 當中。
3. 將新的原始試卷 PDF 下載後，複製到 `d:\test ch\字音形系統\pdf\` 目錄下，確保檔名為 `年份_G年級.pdf` (如 `115_G3.pdf`)。
4. 在命令列執行：
   ```bash
   git add .
   git commit -m "feat: 新增 115 年考題與更新 PDF"
   git push origin main
   clasp push --force
   clasp deploy -i [GAS的部署ID]      # 覆蓋目前 URL 不改變使用者書籤
   ```

### ❓ 情境二：GAS 的部署被限制或 URL 變了怎麼辦？
- 我們已經制定了不建立新 URL 的 SOP。永遠使用 `clasp deploy -i [原Deployment_ID]`，系統會覆蓋原本的發布版本（例如覆蓋 @147），這樣前線老師的連結就永遠不會失效。

### ❓ 情境三：PDF 的預覽有問題或是找不到檔案 (404)？
- **檢查 PDF 路徑**：目前都是向 `https://wukolo1206.github.io/lesson-search/字音形系統/pdf/` 請求。請先從瀏覽器網址列直連該 PDF 看看 Github Pages 是否有該檔案。
- **檢查 `examPages` 變數**：在 `index.html` 前方有一大包 PDF 頁碼對照表 (`examPages`)，確保 `年份_年級_篇名` 有正確映射到頁數。
